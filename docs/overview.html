Todo lo que hicimos, en cinco minutos

La app de trading ya estaba hecha. Nuestro trabajo fue descubrir qué tan buena es, dejar una forma repetible de comprobarlo y contar lo que encontramos. Esto es el mapa; el detalle vive en los otros documentos.

Casos y defectos

Todo vive en Qase (proyecto COCOS) y los HTML de docs/ son su copia legible.

Cómo funciona todo

Una API compartida, dos suites que la miran desde ángulos distintos y un lugar donde termina el resultado.

La API se controla con dos headers.

X-Enable-Bugs elige el nivel de defectos (off, easy, medium, hard). Con off todo debería andar: es la línea base. X-Candidate-Id separa el estado de cada persona, así nadie pisa a nadie.

El saldo se deriva de las órdenes.

No hay un saldo guardado: se calcula desde las órdenes ejecutadas, y cada orden reserva plata o acciones apenas se crea. Por eso varias pruebas comparan portafolio y órdenes entre sí.

Las órdenes límite son inestables a propósito.

Pueden quedar pendientes, ejecutarse o rechazarse al azar. En vez de apostar a un resultado, las pruebas usan órdenes a mercado (que son determinísticas) o precios que nunca se ejecutan, y verifican que el resultado caiga en el conjunto permitido.

Sin POST /reset también se puede.

Cada corrida usa su propio candidate id y datos propios, y las aserciones miran diferencias en vez de valores absolutos. No depende de arrancar desde cero.

Qué encontramos

19 defectos cargados en Qase. Estos son los que más importan.

  • CríticaEn iOS, los rechazos del servicio son silenciosos: la app no avisa cuando la orden no se puede enviar.
  • MayorLa posición desaparece del portafolio mientras una venta límite reserva todas las acciones.
  • MayorLa moneda ARS se puede comprar como si fuera una acción.
  • MayorBuscar por el nombre de la empresa no devuelve nada, aunque el campo lo promete.
  • MayorAndroid nunca muestra el aviso de orden ejecutada.
  • ResueltoEl ticket era inoperable con VoiceOver en iOS.

Cuatro casos automatizados (COCOS-15, 18, 30 y 41) fallan porque la app no cumple; el test es correcto. Están en el reporte de bugs con pasos, esperado, obtenido y evidencia.

Cómo correrlo

Un comando para todo, otro para lo que no necesita dispositivos. 

# todo menos UI: lint, formato, tipos, unitarios y API (~20 s)
bun run qa:rapido

# todo, incluida la UI en Android y iOS (necesita emulador y simulador)
bun run qa

El primer build de release tarda entre 30 y 45 minutos; las corridas siguientes reusan el binario.
